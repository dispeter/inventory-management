Factory Inventory Management System

Demo application for Catalyst Components. A Vue 3 single-page app talks to a Python FastAPI service over REST. All data is loaded from JSON files into memory at startup; there is no database.

System architecture

Three tiers, all running locally. Nothing is persisted between server restarts.

Data flow: changing a filter

The four filters (time period, location, category, order status) are global state. Every view that depends on them refetches when they change.

  1. User changes a filter in FilterBarThe component writes to refs exported by useFilters. They are module-level singletons, so every view shares the same state.
  2. The view's watch() firesEach view watches only the filters it uses. Inventory, Demand and Backlog watch location and category; Dashboard and Orders also watch period and status.
  3. getCurrentFilters() builds the filter objectLocation becomes warehouse and period becomes month. Month is omitted when set to all.
  4. api.js builds the query stringAny filter equal to 'all' is dropped, then axios sends GET /api/orders?warehouse=...&category=....
  5. FastAPI route filters in-memory listsapply_filters() matches warehouse exactly and category and status case-insensitively. filter_by_month() accepts 2025-03 or a quarter such as Q1-2025 and matches against order_date.
  6. Pydantic validates the responseList endpoints declare a response_model, so the JSON shape is checked before it is returned.
  7. The view stores raw data in refsResults land in refs such as allOrders and inventoryItems.
  8. Computed properties derive what is shownKPIs, chart series and table rows recompute from the refs and render as SVG and tables. Dashboard issues four requests in parallel (summary, orders, inventory, backlog).

Known gaps

Mismatches found while reading the code. Items 1 to 3 explain the errors in the browser console on the Overview page.

1. Client calls endpoints the server does not have

api.js calls /api/tasks (GET, POST, DELETE, PATCH) and /api/purchase-orders (POST, GET by backlog item). None are defined in main.py, so App.vue logs a 404 when it loads tasks. The backend does define PurchaseOrder models and loads purchase_orders.json, but only uses them to set has_purchase_order on backlog items.

2. Missing component: PurchaseOrderModal

Dashboard.vue renders <PurchaseOrderModal>, but no such file exists in client/src/components. Vue warns that it cannot resolve the component, and the Create PO buttons cannot open a form.

3. Backlog view is not routed

views/Backlog.vue exists but main.js has no route for it, so it is unreachable from the navigation.

4. Dashboard backlog count ignores filters

total_backlog_items in /api/dashboard/summary is len(backlog_items) regardless of the warehouse or category passed in.

5. Reports bypasses the API client

Reports.vue imports axios and hard-codes http://localhost:8001 instead of going through api.js, so the base URL lives in two places.
